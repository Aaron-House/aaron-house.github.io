GEO / AEO

GEO/AEO 가이드

2025년 7월 1일 발행, 2026년 10월 29일 업데이트. 글 손승완

“GEO 컨설팅 회사 추천해줘.”

이 질문에 검색은 링크를 돌려줍니다. AI는 이름을 돌려줍니다. GEO는 그 이름 안에 우리 브랜드가 정확한 설명과 함께 들어가게 만드는 일입니다.

왜 지금 AI가 고르는 순서 질문 설계 SIFT 자사 측정 실행

왜 지금

답을 읽는 순간, 클릭은 끝나 있습니다

사용자는 링크 열 개를 비교하기 전에, AI가 좁혀 준 이름 몇 개로 후보를 정합니다. 답변에 없으면 비교 대상에도 오르지 않습니다.

국내에서 이 변화가 어떻게 진행되는지는 제로클릭, 맥킨지 보고서, 네이버 검색 점유에서 따로 정리했습니다. 이 페이지는 그다음, 답변에 들어가는 방법을 다룹니다.

AI가 고르는 순서

AI는 브랜드를 고르지 않습니다. 설명 가능한 답을 고릅니다.

위의 답변이 나오기까지 AI가 거치는 순서를, 에이넥트 자사 질문으로 풀어 보면 이렇습니다.

  1. 01

    질문을 상황으로 바꿉니다

    “GEO 컨설팅 회사 추천해줘”에는 브랜드명이 없습니다. AI는 이것을 국내에서 GEO를 맡길 회사를 찾는 구매 상황으로 읽습니다. 브랜드를 이미 아는 사람의 질문과, 아직 고르지 않은 사람의 질문은 다른 답으로 이어집니다.

  2. 02

    출처를 모읍니다

    공식 사이트, 언론 인터뷰, 칼럼, 서비스 페이지. 답변의 문장은 이 페이지들에서 나옵니다. 페이지가 없거나 크롤러가 읽지 못하면, 그 사실은 답에 들어가지 않습니다.

  3. 03

    하나의 주체로 묶습니다

    에이넥트, Ainnect, 손승완이 같은 회사인지. 이름과 설명이 채널마다 다르면 여기서 흩어집니다. AI는 브랜드를 응원하는 것이 아니라, 서로 맞는 정보를 한 주체로 연결할 수 있는지를 봅니다.

  4. 04

    문장으로 합성합니다

    첫 문단에 이름, 하는 일, 근거가 들어갑니다. 링크 열 개 중 하나가 아니라 문장의 주어가 됩니다. 설명이 틀리면 그 틀린 문장이 브랜드의 소개가 됩니다.

GEO의 정의

GEO(Generative Engine Optimization)는 이 네 단계에서 브랜드가 빠지거나 잘못 설명되지 않도록 정보 환경을 정리하는 일입니다. AEO(Answer Engine Optimization)와 같은 대상을 가리키는 말입니다. 검색 결과의 순위를 올리는 SEO와 겹치는 부분은 있지만, 목표가 다릅니다. SEO는 링크가 보이게 하고, GEO는 문장 안에 이름이 정확히 들어가게 합니다.

질문은 설계해야 합니다

네 단계는 질문에서 시작합니다. 브랜드명을 넣은 질문만 보면, 이미 회사를 아는 사람의 답만 보게 됩니다. 아직 고르지 않은 사람이 실제로 말하는 질문을 빠뜨리면, 그다음 출처와 문장도 비게 됩니다.

에이넥트의 질문 설계 프레임워크 AID-Q는 그물망식 질문 설계법입니다. 95% 이상의 발화 질문을 커버합니다. 출처는 에이넥트 자체 데이터 2026.3~2026.8입니다.

SEO, GEO, 그다음

SEO는 검색 결과를, GEO는 AI 답변을 다룹니다. Agent Commerce Optimization은 AI 에이전트가 비교와 구매를 대리할 때의 선택까지 보는, 에이넥트의 다음 단계입니다.

구분 SEO GEO (= AEO) Agent Commerce
목적 검색 결과 상위 노출 AI 답변 속 정확한 인용 에이전트의 선택·거래 후보에 남기
내용 키워드, 온페이지, 백링크 질문 의도, 사실, 맥락, 출처 에이전트가 읽는 구조화 데이터와 API
측정 순위, 클릭률, 유입 SoA, 인용 빈도, 답변 안 위치와 맥락 에이전트 선택률, 거래 완결

방법

네 단계에서 빠지지 않는 조건, SIFT

SIFT는 콘텐츠를 많이 만드는 법이 아닙니다. 위에서 본 순서에서 브랜드가 탈락하지 않기 위한 네 가지 조건입니다.

Structure

읽히는 구조

스키마, 제목 계층, 대표 URL, 내부 링크. AI가 페이지를 열어 사실을 집어낼 수 있어야 합니다.

연결되는 단계 03 하나의 주체

Intent

질문과의 맞춤

실제 구매 질문으로 페이지를 구성합니다. 브랜드명만 반복한 글은 “추천해줘”에 쓰이지 않습니다.

연결되는 단계 01 상황으로 읽기

Fidelity

맞는 말

수치와 사실이 맞고, 홈페이지·보도·칼럼이 같은 말을 합니다. 어긋나면 답변도 어긋납니다.

연결되는 단계 04 문장으로 합성

Trust

받쳐 주는 출처

저자, 회사, 언론, 칼럼이 서로를 가리킵니다. 공식 페이지만 있고 바깥 기록이 없으면 답이 짧아집니다.

연결되는 단계 02 출처를 모으기

실행 체크 12가지

콘텐츠 4가지, 기술 8가지. 필요한 쪽만 펼쳐 보면 됩니다.

콘텐츠 GEO 4가지

  1. 1. Direct Answer 우선 배치

    첫 문단에서 질문에 대한 직접적인 답을 먼저 제시한다. 서론으로 답을 미루지 않는다.

  2. 2. AI가 파싱하기 쉬운 포맷

    긴 줄글 대신 bullet, 번호 목록, 비교표, 단계 설명처럼 구조가 보이는 형식을 쓴다.

  3. 3. 엔티티 밀도와 자연어 헤딩

    관련 개념·제품명·브랜드명을 충분히 두고, 제목은 사용자가 AI에게 물어볼 법한 문장으로 쓴다.

  4. 4. 이 페이지에서만 얻는 정보

    어디서나 볼 수 있는 일반론 대신, 통계·사례·관점처럼 이 페이지에만 있는 정보를 넣는다.

테크니컬 GEO 8가지

  1. 1. 사이트맵과 검색엔진 등록

    Google Search Console과 Bing Webmaster에 사이트를 등록하고 사이트맵을 제출한다.

  2. 2. robots.txt 크롤러 권한

    AI 크롤러의 허용 범위를 정하고, 중요한 페이지를 실수로 막지 않았는지 본다.

  3. 3. Canonical URL

    rel="canonical"로 대표 주소를 지정해 인용과 신뢰 신호가 한곳으로 모이게 한다.

  4. 4. JSON-LD 스키마

    Article, FAQ, Organization 등에 dateModified, author, publisher, sameAs를 빠뜨리지 않는다.

  5. 5. SSR 또는 Static

    자바스크립트를 실행하지 않아도 본문을 읽을 수 있게 렌더링한다.

  6. 6. RSS 피드

    feed.xml 또는 feed.json을 제공하고 head에 alternate 링크를 둔다.

  7. 7. IndexNow

    글을 올리거나 고치거나 지울 때 Bing 등 파트너 엔진에 변경을 알린다.

  8. 8. 정기 점검

    canonical, JSON-LD, 피드, IndexNow가 의도대로 도는지 주기적으로 확인한다.

측정

같은 질문을, 숫자로 봅니다

고객사 화면은 공개하지 않습니다. 아래는 에이넥트 자사를 ChatGPT·Gemini·Claude·Perplexity와 네이버 AI 브리핑에서 측정한 화면입니다. 언급률, 답변 점유(SoA), 인용 출처는 질문 세트와 시점을 정해 반복해서 기록합니다. 한 번 나온 순위를 성적표로 쓰지 않습니다.

실행

진단하고, 고치고, 다시 측정합니다

  1. 1. 현황을 숫자로 고정합니다

    브랜드명 없는 질문 세트를 만들고, 4대 엔진과 네이버 AI 브리핑에서 자사와 경쟁사가 어떻게 소개되는지 기록합니다. 이 기록이 이후 변화의 기준입니다.

  2. 2. 빠진 단계부터 고칩니다

    답에 이름이 없으면 질문과 출처를, 이름이 있는데 설명이 틀리면 공식 정보와 바깥 기록의 불일치를 먼저 봅니다. SIFT와 위의 체크 12가지가 고치는 순서입니다.

  3. 3. 같은 질문으로 다시 봅니다

    월 단위로 같은 질문을 다시 던져 언급, 점유, 인용의 맥락이 바뀌었는지 확인합니다. 한 번의 진단으로 끝내지 않습니다.

실행까지 해야 컨설팅입니다.

숫자만 전달하고 끝나면 바뀌지 않습니다. 에이넥트의 PM팀은 기업의 제품과 브랜드전략, 웹사이트, PR, 마케팅을 모두 이해하고, 직접 들어가서 개선합니다.
